# 0032. atoom 0.8.0: the audit transports NATS and SQS, and the AppConfig source

Status: accepted, 2026-11-25 (owner decisions D44 A, D65 A and D71 A)
Date: 2026-11-25

Fills the two seams that [0030](0030-lambda-handlers-step-5-choices.md) left for atoom's B9, in the change that moves session to atoom 0.8.0. It keeps every rule of [0024](0024-audit-transport-is-an-explicit-switch.md) (exactly one place for the records, chosen by an explicit switch, never by a name of an installation) and of [0025](0025-first-version-for-the-first-sites.md) (no key rotation at the first sites).

## Context

atoom 0.8.0 releases three Go drivers that a host links in its own process:

- `transport/nats`, the NATS JetStream driver of the transport port. Emit publishes to a subject the host names with `Nats-Msg-Id` set to the message's uid, so JetStream drops a retry within the stream's duplicate window; the answer waits for JetStream's acknowledgement. The connection and its credentials are the host's. Moved forward for session's first site by the owner's D65 A.
- `transport/sqs`, the Amazon SQS driver: one FIFO queue, one message group, the deduplication id the SHA-256 of the uid. The audit transport of a Lambda function, which has no spool sidecar (the owner's D44 A, 0030).
- `source/appconfig`, the AWS AppConfig driver of the source port: one application and environment the host names, a document is a configuration profile, `POLL` with AppConfig's interval. Built before `source/ssm` by the owner's D71 A; 0030 chose it for the Lambda shape.

0.8.0 also brings the rotation ring of the token block (atoom's B8b). session's first sites run without rotation (0025), so it is not adopted here.

## Decision

### atoom

| Subject | Choice |
| --- | --- |
| atoom | Every atoom module at 0.8.0, one version, as before; `go.mod` adds `transport/nats`, `transport/sqs` and `source/appconfig`. `spike/` keeps the pins it ran with |
| The audit emitter | `truvity/audit/emitter` stays at 0.19.0; the build selects atoom 0.8.0 for it |
| The rotation ring | Not adopted. A purpose without a ring works as before in 0.8.0, and the first sites rotate no signing key (0025). It is the next step, before the first site that rotates a key |

### The audit transport: four switches, exactly one

| Switch | Driver | For |
| --- | --- | --- |
| `--audit-socket PATH` | The emit socket of a transport driver beside the process (`transport-spool`) | A cluster with the spool sidecar, as before (0024) |
| `--audit-nats URL` | atoom's Go `transport/nats`, in the process | A site whose audit writer consumes a NATS JetStream stream |
| `--audit-sqs QUEUE_URL` | atoom's Go `transport/sqs`, in the process | A Lambda function (0030) |
| `--audit-stdout` | `internal/audit.Lines`, in the process | Local development, as before (0024) |

Exactly one of the four; none, two or more are refused at start, and the message names the switches given. `--audit-scope` stays a label only ([0027](0027-atoom-0.7.0-and-the-audit-scope-flag.md)).

The settings of `--audit-nats`, all refused without it:

| Flag | Meaning |
| --- | --- |
| `--audit-nats-stream NAME` | The JetStream stream of the log. Required |
| `--audit-nats-subject SUBJECT` | The subject session publishes to, which the stream captures. Required |
| `--audit-nats-creds FILE` | A NATS credentials file (a user JWT and its seed) |
| `--audit-nats-token-file FILE` | A file holding a token, read at every connect, so a token the deployment renews is the current one. Refused with `--audit-nats-creds` |
| `--audit-nats-tls-ca FILE` | A PEM file of the CAs that sign the server's certificate |

The deployment makes the stream (its storage, replicas and duplicate window) and the writer's consumer; session turns off the driver's `Create` and needs only to publish on the subject and `STREAM.INFO`. The driver's options name a durable consumer even for a host that only emits; session passes the constant `session-emits-only`, which an emit never reads. The connection retries in the background from the start: while NATS is down, a sign-in fails closed and every other event is lost and counted, as with any transport (0008), and the check goes on.

`--audit-sqs` takes the URL of a FIFO queue; atoom's driver refuses one that does not end in `.fifo`. The queue, its visibility timeout, its redrive policy and its encryption are the deployment's. The SQS client takes its region, credentials and any endpoint of another place from the AWS SDK's configuration, as the DynamoDB and KMS clients do.

The emitter name both in-process drivers carry (`Atoom-Emitter`, `atoom-emitter`) is `session`, the product.

### The source: two switches, exactly one

| Switch | Driver |
| --- | --- |
| `--config-dir DIR` | atoom's Go `source/file` over a directory, as before; on Lambda, the configuration layer of [0012](0012-lambda.md) |
| `--source-appconfig APP/ENV/PROFILE` | atoom's Go `source/appconfig`, in the process: the application `APP` and its environment `ENV`, names or ids |

Exactly one; none or both are refused at start, and a value that is not three non-empty parts separated by `/` is refused. The site file is the configuration profile `PROFILE`; every other document the site file names (the policy bundle, the error page) is the profile of its own name, so one site file reads the same from a directory and from AppConfig. The documents are the same signed bytes on both. The AppConfig client takes its region, credentials and endpoint from the AWS SDK's configuration (`AWS_ENDPOINT_URL_APPCONFIGDATA` for another place). The poll interval is AppConfig's (60 seconds by default); the driver calls AppConfig at most once in each interval for each document.

`--source-appconfig` is a switch of every shape, not of Lambda alone: session decides nothing by where it runs.

## Consequences

- A Lambda function now runs with its records going to a writer: `session authorizer` and the sign-in function take `--audit-sqs` and `--source-appconfig`. What is left of step 5 is the packaging under `lambda/` and the real-AWS run.
- A site on a cluster may use `--audit-nats` in place of the spool sidecar; the first sites keep `--audit-socket` (0025).
- `go.mod` gains `nats.go` and the AWS SDK's `sqs` and `appconfigdata` clients; `nats-server` is in the module graph through atoom's test helpers and is not built into session.
- `just test-nats` runs `--audit-nats` against a NATS server with JetStream in a container (pinned by digest in the Justfile), in the CI job of the containers: a sign-in's record lands once, and a retry of its message is one message. atoom's own kit runs its driver against an embedded server.
- `--source-appconfig` is tested through the real AWS SDK client against a small fake of AppConfig's data plane in `cmd/session`; atoom's fake is internal to its module.
- `--audit-sqs` is tested at start only (the FIFO rule, exactly one switch); its emit is atoom's, tested against ElasticMQ by atoom's kit.
- Not tested here: NATS over TLS, a credentials file, a cluster; SQS and AppConfig themselves. They are the deployment's to check, as atoom's driver pages say.

## Roads not taken

| Road | Why not |
| --- | --- |
| `--audit-nats` on a NATS transport driver beside the process, through `--audit-socket` | Works today for a cluster with a sidecar, and stays possible; the in-process driver needs no sidecar, which is why D65 A moved it forward |
| `--audit-nats-consumer` | session never consumes; a flag for a value nothing reads |
| `--audit-nats-create` (the driver makes the stream) | The deployment owns the stream's storage and limits, and session's user then needs no right to make one |
| A single `--audit URL` with a scheme (`unix:`, `nats:`, `sqs:`) | One flag that means four things, and the NATS settings still need flags of their own |
| `--source-appconfig APP/ENV` with every document under its own name | The site file's profile is the one name a deployment must choose; the others follow from the site file |
| An `--audit-sqs-message-group` or `--source-appconfig-poll` flag | The drivers' defaults serve one emitter and one function; a flag when a site needs another |
| The rotation ring now | No first site rotates a key (0025); the ring is the next step |
